# PVE-03 / OptiPlex 3080 audit - 3 October 2026

This document records a full baseline audit of the Dell OptiPlex 3080 Proxmox node `pve3080`. The purpose of the session was not only to verify that the node was healthy, but also to practise a repeatable server-auditing workflow covering updates, hardware, storage, networking, services, logs and configuration hygiene.

- CPU topology: 6 cores / 12 threads
- RAM: 16 GB DDR4-2666 (2 x 8 GB)
- Maximum memory reported by SMBIOS: 64 GB across 2 slots
- System disk: Samsung MZ7LN256HCHP 256 GB SATA SSD

- Wi-Fi / Bluetooth: Intel Wi-Fi 6 AX200

## 1. Proxmox and kernel update

The node started the session on:

- Kernel `7.0.14-19-pve`

After refreshing APT metadata, 16 packages were available for upgrade. The update included Proxmox components, QEMU packages, security updates and a new signed kernel.

The system was upgraded with:

```bash
apt update
apt list --upgradable
apt full-upgrade
```

The upgrade completed without package removals. After reboot, the active versions were verified with:

```bash

uname -r
```

Final versions:

- Proxmox VE 9.2.21
- Running kernel `7.0.14-20-pve`

### Learning point

Installing a new kernel does not mean it is active immediately. The server must reboot and the running kernel must be verified afterwards.

### Learning point

Testing the gateway, then a public IP, then a DNS name separates Layer 3/local routing, Internet reachability and DNS resolution. This makes network troubleshooting much more precise.

## 7. Persistent network configuration

The persistent configuration was checked in:

```bash
cat /etc/network/interfaces
```

The active bridge configuration is:

```text
iface nic0 inet manual

auto vmbr0
iface vmbr0 inet static
        address 192.168.1.166/24
        gateway 192.168.1.254
        bridge-ports nic0
        bridge-stp off
        bridge-fd 0
```

The file also contained an unused line:

```text
iface nic1 inet manual
```

Investigation showed that `nic1` did not exist:

```bash
ip link show nic1
grep -R "nic1" /etc/network/interfaces /etc/network/interfaces.d/ 2>/dev/null
```

Before editing, a backup was created:

```bash
cp /etc/network/interfaces /etc/network/interfaces.bak
```

The orphaned `nic1` line was removed, and the change was verified with:

```bash
diff -u /etc/network/interfaces.bak /etc/network/interfaces
```

No active interface or bridge settings were changed.

### Learning point

Configuration cleanup should follow a safe sequence: identify the stale entry, search for dependencies, create a rollback copy, make the smallest possible change, then verify the diff.

## 9. Proxmox services and logs

Failed services were checked with:

```bash
systemctl --failed
```

Result:

- 0 failed units

Core Proxmox services were explicitly checked:

```bash
systemctl is-active pveproxy pvedaemon pvestatd pve-cluster
```

All four were active.

Errors from the current boot were reviewed with:

```bash
journalctl -p 3 -b --no-pager
```

The log contained no evidence of a current storage, network or Proxmox service failure. A single failed `root@pam` login was traced back to a known desktop on the LAN by checking the neighbour table and local hostname resolution.

### Learning point

A useful investigation chain is:

1. Find the event in the logs.
2. Identify the source IP.
3. Check the neighbour/MAC entry.
4. Resolve the IP to a known hostname.
5. Decide whether the event is expected or suspicious.

### Learning point

A Linux filesystem can run out of either storage blocks or inodes. `df -h` checks capacity in bytes, while `df -i` checks inode exhaustion.
